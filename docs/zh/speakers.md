# 说话人

## 两个问题

| 问题 | 机制 |
|------|------|
| **谁** 说了这段？ | 说话人 **识别**（embedding 匹配） |
| **何时** 换人？ | VAD 静音切段 +（未来）diarization / 换人点 |

当前流程会为每个 VAD 语音段分配一个说话人 ID，还不能检测语音段内部的说话人切换，因此不属于完整的说话人分离（diarization）。

## 识别路径

1. 3D-Speaker CAM++ embedding  
2. 质心 + 余弦相似度 + EMA（`speaker-tracker.ts`）  
3. 长段 **多窗投票**（减轻插嘴污染）  
4. 阈值默认约 **0.55**（`--spk-threshold`）  

关闭：`--no-spk` / setup `--skip-spk`。

## 全局名册

`~/.config/baribari/speakers/roster.json`

- 开播先加载为槽 `1…G`  
- TUI 说话人列表 **Enter 改名** → 写入名册  
- 退出会话可写回 EMA 更新  
- 之后会议声纹匹配自动贴名  

## 合并 UX

- 直播/回放：`m` 多选合并；`1`–`9` 指派上一段（直播、说话人焦点）  

## 设计硬限制

| 场景 | 表现 |
|------|------|
| A→B 无缝、几乎无静音 | 常并成 **一段一人** |
| 重叠/抢话 | 投票出一个主说话人，可能错 |
| 同人漂移 | 无名册时可能拆成两人 |

更换 SenseVoice 模型无法解决这些问题，因为语音识别和说话人识别是两个独立任务。

## 与 sherpa 文档对齐的方向

| 做法 | 适配 |
|------|------|
| 会前注册声纹 | 强化 ID；扩展名册 |
| 段内 embedding **换人点** 切开 | 改善无缝换人 |
| Offline **pyannote + embedding + 聚类** | 适合 **会后** 对 `audio.wav` 重标 |
| 每句完整 diar | 对「跟手实时」通常过重 |

Offline diar 样例 RTF 约 0.1–0.3，**快于实时但偏批处理** — 适合清理会话，不适合句中插话级标注。
