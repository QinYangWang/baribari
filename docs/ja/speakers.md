# 話者

## 二つの問題

| | 手段 |
|--|------|
| **誰** が話したか | 話者 **識別**（embedding） |
| **いつ** 交代したか | VAD 無音 +（将来）diarization / 変化点 |

現在は VAD で分割した発話区間ごとに一つの話者 ID を割り当てます。区間内の話者交代まで検出する完全な diarization ではありません。

## 識別

CAM++ で声紋 embedding を計算し、重心、コサイン類似度、EMA 更新を使って照合します。長い発話区間では複数の時間窓で投票します。既定のしきい値は約 0.55 です。話者識別が不要な場合は `--no-spk` を指定します。

## グローバル名簿

`~/.config/baribari/speakers/roster.json`  
ライブ文字起こしの開始時に、名簿を話者スロット `1…G` として読み込みます。TUI で自動検出された話者を選び、`Enter` で改名すると名簿へ保存されます。終了時には、更新された EMA の値を書き戻すこともできます。

## UX

`m` 統合 · `1–9` 直前セグメント割当（ライブ・話者フォーカス）。

## 限界

無音を挟まない話者交代、重なった発話、同じ人の声の変化は誤判定しやすい場面です。SenseVoice を別のモデルに替えても、音声認識と話者識別は別の処理であるため、この問題は解決しません。

## 今後

名簿登録強化 · 区間内変化点切断 · 会後 offline diarization（pyannote 等）。  
Offline diar は RTF&lt;1 でも **バッチ向き** — ライブ割り込み用途ではない。
